01 · The comparison

Two ways to delete a document.

GhostCache runs the same deletion two ways: once naively, as a deliberately broken control, and once by following provenance. The source document is emptied either way. The difference is everything that was derived from it.

02 · The controlled corpus

Five fictional documents, one fresh secret.

Every run seeds the same five fictional documents about an observatory. Only the passphrase changes: each reset generates a new MOTH- marker, so a pass can never rely on an old one.

  • d-vaultVault access note

    The source that is withdrawn. Holds the fictional passphrase and names the reading room.

  • d-gardenRoof garden timetable

    An unrelated opening time, 07:40, that must stay answerable.

  • d-archiveIndependent archive directory

    Names the reading room, Lantern Hall, independently of the vault note, so that fact must survive.

  • d-maintenanceTelescope maintenance plan

    An unrelated schedule. Its chunk feeds the handoff summary.

  • d-shuttleVisitor shuttle guide

    An unrelated departure that retrieval pulls in beside the vault question.

From them, seeding derives five search chunks (one per document), three model-written summaries chained s-vault → s-mixed → s-handoff, and one saved answer: fourteen artifacts. Every generated artifact records every artifact it was given as a parent. The summary prompt asks the model to keep the passphrase on purpose, which builds a known, traceable propagation path; GhostCache does not measure how often secrets leak naturally.

04 · The balance

Remove the secret. Keep the facts.

A cleanup that destroys everything would pass a "secret is gone" test trivially. So every evaluation asks six recorded questions: two must reveal the marker (proving the failure was real), two must not, and two must still answer facts that should survive.

05 · Timing evidence

What the clock recorded.

Each report records the duration of every model call. The October 28 runs came one after the other: the first right after Ollama was started (cold), the second straight afterwards (warm). The October 27 run was a separate session.

06 · Scope and limits

Where the claims stop.

  • Application-managed memory onlyCleanup covers GhostCache's SQLite titles and bodies, its recorded provenance and its retrieval. It is not model-weight unlearning or secure disk erasure.
  • The evaluator keeps the markerThe expected marker stays in evaluator state, saved reports, screenshots and this site, on purpose: they are the evidence.
  • Bounded, exact-match checksOne literal marker across four fixed questions. That is not proof that every paraphrase or inference is gone.
  • Lexical retrievalTerm overlap, not embeddings; the reworded question still shares words with its target.
  • A deliberate propagation pathThe summary prompt asks the model to keep the passphrase, so the copies are expected, not discovered.
  • Three runs are not a rateOne model, one laptop, two days. Failures from future runs belong in the record too.
  • Provenance has to be capturedA copy made outside the store is outside the graph, and no traversal can find it.
  • Fictional data onlyNo uploads, no real documents, no connectors to other RAG systems, and no claim about any other product.
